# تطبیق IBSng Agent با نصب واقعی شما (قدیمی)

IBSng هیچ API رسمی (REST/XML-RPC) عمومی برای عملیات مدیریتی (ساخت/حذف/لاک یوزر) ندارد. تنها راه امن و
سازگار با منطق داخلی IBSng (اعتبارسنجی، بایند ISP/Group، هش پسورد، لاگ‌ها) این است که همان درخواست‌های HTTP
که مرورگر شما هنگام کار دستی با پنل ادمین IBSng (`admin/*.php`) می‌فرستد را برنامه‌ریزی‌شده تکرار کنیم. این
یعنی `ibsng-agent/src/IBSngAdminClient.php` باید با **نام دقیق فیلدهای فرم و آدرس دقیق صفحات نصب شماست**
تنظیم شود؛ این‌ها می‌توانند بین نسخه‌های مختلف IBSng کمی فرق کنند، پس به‌جای حدس زدن، مقادیر را از خودِ نصب
شما استخراج می‌کنیم.

## چرا این‌طوری و نه اتصال مستقیم به دیتابیس IBSng؟

اگر مستقیم روی جدول‌های داخلی IBSng (`INSERT`/`UPDATE`) عملیات انجام دهیم، منطق‌هایی که خودِ IBSng هنگام ساخت
یوزر (هش کردن پسورد با الگوریتم خودش، لاگ داخلی، همگام‌سازی با RADIUS، اعتبارسنجی ISP/Group) انجام می‌دهد را
دور می‌زنیم و ریسک خراب شدن داده یا ناسازگاری با لایسنس IBSng وجود دارد. بنابراین فقط برای **خواندنِ تعداد
آنلاین‌ها** مستقیم به جدول استاندارد FreeRADIUS یعنی `radacct` وصل می‌شویم (این جدول ساختار شناخته‌شده و
پایداری دارد و صرفاً خواندنی است، پس ریسکی ندارد). همهٔ عملیات نوشتنی از طریق همان فرم‌های وب انجام می‌شوند.

## قدم‌به‌قدم استخراج مقادیر لازم (با DevTools مرورگر)

روی سیستم خودتان (همان‌جایی که هرروز با IBSng کار می‌کنید) این مراحل را انجام دهید:

1. مرورگر Chrome/Firefox را باز کنید، وارد پنل ادمین IBSng شوید (`http://<ibsng-ip>/admin/index.php` یا هرچه
   آدرس واقعی‌تان هست)، `F12` را بزنید و به تب **Network** بروید، گزینهٔ Preserve log را فعال کنید.
2. **برای Login:** صفحه را رفرش کنید و فرم لاگین را با یوزر/پسورد ادمین بزنید. روی درخواستی که در Network
   ظاهر می‌شود (معمولاً `index.php` با متد POST) کلیک کنید → تب Payload/Form Data → نام دقیق فیلدها (مثلاً
   `admin_username`, `admin_password` یا `user`, `pass`) و مقدار Cookie ست‌شده در پاسخ (`Set-Cookie`) را در
   `config.php` بخش `login` وارد کنید.
3. **برای Add New User:** به تب User بروید، Add New User را باز کنید، فرم را با یک یوزر تستی (که بعداً حذفش
   می‌کنید) پر کنید و Submit بزنید. در Network روی درخواست POST کلیک کنید → Payload را کامل کپی کنید. باید
   فیلدهایی شبیه این‌ها ببینید (نام دقیق را از نصب خودتان بردارید، این‌ها فقط نمونه‌اند):
   - شمارش/الگو: `count`, `username` یا `user_name`
   - `group_id` یا `group`
   - `credit1`, `credit2`
   - `isp_id` یا `isp`
   - پسورد: `password` + احتمالاً یک چک‌باکس/دراپ‌داون برای Auto Generate (`auto_gen_pass` یا مشابه) و طول
     پسورد (`pass_len`)
   - آدرس دقیق submit (مثلاً `admin/user_add.php` یا `admin/index.php?type=...`) از تب Headers → Request URL
4. **برای Search User:** از تب Search User یک یوزرنیم را جستجو کنید → آدرس/فیلد `username` یا `search_field`
   برای جستجو، و از HTML نتیجه لینکی که به صفحهٔ ویرایش همان یوزر می‌رود (معمولاً حاوی `user_id=` است) را
   یادداشت کنید.
5. **برای Lock کردن:** طبق مراحلی که خودتان توضیح دادید، وارد صفحهٔ یوزر شوید → تب Main → تیک `User is
   Locked` → Edit → OK. هرکدام از این کلیک‌ها یک درخواست جدا در Network ایجاد می‌کند؛ حداقل درخواست نهایی
   (همان که بعد از زدن OK می‌رود) را لازم داریم؛ Payload آن را کپی کنید (باید یک فیلد مثل `is_locked=1` یا
   `user_locked=on` داشته باشد به‌همراه بقیهٔ فیلدهای فرم که باید بدون تغییر دوباره فرستاده شوند چون خیلی از
   پنل‌های PHP قدیمی کل فرم را با هم پردازش می‌کنند نه فقط فیلد تغییریافته).
6. همهٔ این مقادیر (نام فیلد، آدرس صفحه، متد) را در `ibsng-agent/config.php` زیر کلید `'form_map'` وارد کنید؛
   هرجا `VERIFY_ME` نوشته شده دقیقاً همان‌جایی است که باید جایگزین کنید.

## تست بعد از تنظیم

```bash
# روی سرور IBSng، بعد از پر کردن config.php
php -r 'require "/opt/ibsng-agent/src/bootstrap.php"; var_dump((new App\IBSngAdminClient(App\Config::load()))->login());'
```

اگر `true` برگشت یعنی لاگین خودکار درست کار می‌کند. بعد از آن یک یوزر تستی از طریق endpoint واقعی agent
بسازید (`curl -X POST http://127.0.0.1:9090/users/create ...`) و در پنل ادمین IBSng بررسی کنید که واقعاً
ساخته شده، سپس همان را از پنل ادمین IBSng پاک کنید.

## اگر بعداً به دیتابیس/سورس IBSng دسترسی مستندتری پیدا کردید

معماری این‌طور طراحی شده که تعویض روش (از HTML-scraping به مثلاً فراخوانی مستقیم توابع داخلی IBSng در همان
سرور، اگر سورس PHP آن در دسترس باشد) فقط به معنی نوشتن یک پیاده‌سازی جایگزین برای `IBSngGatewayInterface`
است؛ هیچ‌کدام از پنل ادمین/Reseller/ربات تلگرام در Host vaset نیازی به تغییر ندارند چون آن‌ها فقط با این
اینترفیس صحبت می‌کنند، نه مستقیم با IBSng.
